# SceneCaptions audit, 24 October 2026

Historical baseline: inspection and reproductions below preceded remediation and model calls. See [the later fixes and diagnosis](2026-10-24-fixes.md) for current outcomes. This original audit was conducted in the main session without agents, model-generation calls, publication or deployment. It is a scoped review, not accessibility certification, paper replication or participant evaluation.

## Overall assessment

Keep the existing prototype. Fresh tests and browser checks establish a useful working base. Several interaction and research-readiness defects need focused repair; the findings do not justify deleting the repository or architecture history.

The interface has a coherent viewing/settings structure, source attribution, visible controls, original override, an independent draft preview and accessible labels in inspected paths. Technical operation is stronger than the current caption-quality and study-readiness evidence.

## Confirmed findings

### P1: Readability changes discard unfinished content preferences

Location: `src/components/workspace.tsx:49`, `src/components/preferences.tsx:25`.

Reproduction: choose Rich without applying, open Caption readability and select Extra large. The detail draft changes from 3 back to 2; the readability panel closes. Saved content remains at 2, as it should, but the unfinished draft is lost.

Cause: the Preferences key includes the entire saved profile. A readability change updates that profile and remounts the component, resetting draft/disclosure state. React documentation confirms this key behavior. Recommendation: separate draft content from immediately applied readability state and retain stable component identity; explicitly reset only at intended boundaries. Regression must check both draft preservation and baseline readability parity.

### P1: Adaptation exceeds the newly agreed viewer detail maximum

Location: `src/lib/captions.ts:63`.

Reproduction: apply Essential with density adaptation enabled and jump to the first sparse cue. The caption is `[Music with a serene character]` instead of the requested minimal `[music]`.

Cause: sparse cues unconditionally select detail 3. The user chose detail as a maximum during the audit. Recommendation: cap selected detail at the chosen limit, update explanatory text and add a regression across all profile/scene combinations. This is an agreed behavior change, not evidence that the earlier implementation contradicted an already settled maximum rule.

### P1 for study readiness: Expanded wording can be impractical at source timing

Location: `data/captions/big-buck-bunny.json`, cue `bbb-sdh-005` and other short intervals.

Measured example: the richest wording contains 68 characters, including a newline, over 0.541 seconds (about 126 characters/second). This audit does not assert a universal DHH reading-speed threshold, but such examples require an explicit review before study use. Recommendation: review word length against cue duration and overlapping events; shorten variants or deliberately review timing changes rather than silently extending captions. Human/DHH readability feedback remains necessary.

### P1 for setup portability: Demo extraction fails without unzip

Location: `scripts/fetch-demo.mjs:17`.

Fresh `npm run setup:demo` downloaded the official archive, then failed with `Install unzip to extract the demo video` on this Windows machine. The documentation does list unzip as required, so this is a portability/setup dependency rather than a concealed requirement. Recommendation: provide and test a supported Windows extraction route or make dependency setup practical. For audit only, Python extracted the single movie entry to the intended destination and its hash matched `738e2f999860553d056dd79c952f58f63cbb73892a57c72342ce9e5330d9d2d7`.

### P2: Rehearsal misses an already enabled original override

Location: `src/components/workspace.tsx:51`, `src/components/study-rehearsal.tsx:10`.

Reproduction: turn Show original on, start a rehearsal, immediately export. The export contains initial condition/profile but no starting original-override state, despite the source caption being displayed. Final condition is personalized and no final override flag is present. Cause: initial events/payload omit this state. Recommendation: record it at the start and in the final snapshot; review whether playback speed/mute are needed for the eventual approved protocol. The export is rehearsal-only, but its current contents cannot reconstruct the complete caption state.

### P2: Preview action wording can mislead

Location: `src/components/preferences.tsx:21`, `src/components/workspace.tsx:41,49`.

The draft caption appears in a separate panel, while `Preview this cue in the video` only seeks and retains the applied overlay settings. The helper text admits this after activation. Also the selected sample is the next cue (or first cue), not always the currently active cue. Recommendation: make the seek-only action explicit or design an unmistakable temporary preview state that preserves the saved profile. Resolve the intended interaction before implementation.

### P2: Small controls and very small explanatory text need a focused accessibility pass

Location: `src/app/globals.css` and playback/preferences controls.

Measured at 390px: play/mute/fullscreen controls are 28x30px; the switch input is 34x20px; several explanatory labels use 8–11px CSS text. These are usability concerns for the intended audience, not an automatic declaration of a WCAG failure: spacing, associated labels and applicable exceptions need evaluation. Recommendation: improve practical target areas and explanatory text readability, then verify keyboard/touch and enlarged viewing. Desktop/tablet remain the proposed study targets.

### P2: Research, domain and status documents have drifted

The plan still describes illustrative captions and scene tags while the working sample uses licensed captions and a density proxy. The old glossary called original captions illustrative; that definition was corrected during this audit. `architecture.txt` still contains historical implementation descriptions, so use the decision log and current-state links to distinguish them.

The proposal notes sometimes generalize the 2–8 minute setting to all three related papers. Bounded primary-source checks confirmed CapTune section 7.7 describes 2–8 minute clips. Interpretive Caption describes a 30-minute remote session with about five minutes of prototype interaction; session duration is not film duration or a non-speech experiment. CuCap's detailed claims remain unverified here. Correct later research materials without changing the preserved source proposal files.

### P2 for automated-generation setup: Environment key name differs

The local file contains `NVIDIA_KEY`, while `scripts/nim_client.py` reads `NVIDIA_API_KEY`. Presence was checked without displaying the value. Recommendation: support/document the intended name before a bounded authorized request. No endpoint test occurred in this audit; existing historical model authentication is not proof that the newly supplied key works.

## Research and architecture review

- Sound detection, caption rewriting and visual-context analysis are distinct capabilities. A valid JSON response is not evidence that a sound occurred.
- Keep the failed Omni audio gate and the working licensed-caption path separate. New text generation can be evaluated against trusted captions without pretending raw-audio recognition works.
- The proposed between-participants design avoids replaying the same story in two conditions. Its small feasibility sample and bundled-feature comparison cannot establish independent effects of adaptation, preview or each control. Final choices and instruments need approval/piloting.
- CapTune section 7.7 explicitly identifies limitations in long-form evaluation and output reliability. Its public repository README describes live model transformation in the viewer. Therefore describe offline precomputation as SceneCaptions' chosen architecture; do not attribute it uncritically to CapTune. Reuse feasibility/license acceptance is still unresolved; no upstream code was imported.
- Preserve local-only keys, rights-clear source provenance and no viewing-time model calls. Participant consent, controlled storage, recruitment and reviewed study media are separate unimplemented preparation.

Primary source for the repository comparison: [CapTune repository](https://github.com/SoundabilityLab/CapTune). Local paper extracts were generated for bounded checking and now live in ignored `artifacts/research-extracts/2026-10-24/`; this is not a full claim-by-claim literature review.

## Design assessment

Implementation integrity: coherent player, separate settings panel, reusable visual tokens and genuine controls; preserve the foundation. Draft/applied/readability state needs repair. Caption reading-time review outranks decorative changes.

Accessibility, performance, theming and responsive behavior are only partly measured. No overall compliance/health score is assigned: this review did not establish full WCAG conformance, physical touch behavior, every state, or a performance profile. The proposed light interface is intentional; an absent dark theme is not automatically a defect.

Recommended design actions after agreement: clarify preview wording, harden state handling, adapt practical controls/text, and finish with a focused polish/recheck. These are priorities, not additional automatically invoked workflows.
